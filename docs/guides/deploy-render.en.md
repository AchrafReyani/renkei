# Deploying to Render (free tier)

> 日本語: [deploy-render.ja.md](deploy-render.ja.md)

Run renkei as a free Render web service. The public demo (`https://renkei-demo.onrender.com/dev`) is deployed exactly this way. Time: ~15 minutes. You need: a Render account (GitHub-connected) and a Postgres (Neon free tier).

> **Free-tier caveat**: the service sleeps after 15 minutes without traffic and takes **up to a minute** to wake on the next request. Render also **occasionally returns 404 or nothing at all** while the app logs stay clean. Fine for a demo or evaluation; use a paid plan or [Fly.io](deploy-fly.en.md) for anything real. Render's free Postgres is deleted after 30 days, which is why the database lives on Neon.

## 1. Postgres (Neon)

Create a project on [Neon](https://neon.tech) (Singapore is the region closest to Render's) and note the connection string (`postgres://...?sslmode=require`). renkei runs its migrations on boot.

## 2. Generate the signing key

```sh
node -e "
const { generateKeyPair, exportJWK } = await import('jose');
const { privateKey } = await generateKeyPair('RS256', { modulusLength: 2048, extractable: true });
const jwk = await exportJWK(privateKey);
console.log(JSON.stringify([{ ...jwk, kid: 'k' + Date.now().toString(36), alg: 'RS256', use: 'sig' }]));
" --input-type=module
```

Paste the output (a one-line JSON array) as `RENKEI_JWKS` in the next step. The cookie key is generated by Render (`generateValue: true`).

## 3. Apply the Blueprint

The repo root has a `render.yaml`.

1. Render dashboard → **New → Blueprint** → pick this repository
2. It prompts for the `sync: false` variables: `LINE_LOGIN_CHANNEL_ID`, `LINE_LOGIN_CHANNEL_SECRET`, `DATABASE_URL` (step 1), `RENKEI_JWKS` (step 2)
3. **Apply** → the first build takes 3–5 minutes

If the service name is already taken, Render appends a suffix. Then fix **Environment → `ISSUER`** to the actual URL and redeploy — `ISSUER` is the OIDC issuer and must match exactly.

## 4. Register the callback on the LINE side

LINE Developers Console → Login channel → **LINE Login → Callback URL** → add
`https://<service>.onrender.com/line/callback` ([console guide](line-console.en.md#2-create-a-line-login-channel)).

## 5. Verify

```sh
curl https://<service>.onrender.com/.well-known/openid-configuration   # issuer must be your URL
open https://<service>.onrender.com/dev                                 # the test RP
```

You are done when `/dev` completes a LINE login — friend-add screen, then an id_token carrying `line:*` claims. The first request after idle is slow: that's the wake-up.

## What to change for production

| | Free demo | Production |
|---|---|---|
| `plan` | `free` (sleeps) | `starter` or above |
| `RENKEI_DEV` | `true` (exposes `/dev`) | remove; register your apps in `RENKEI_CLIENTS` |
| Postgres | Neon free tier | something with backups |
| `autoDeploy` | default (redeploys on push to main) | pin a branch or deploy manually |

## Common errors

- **`redirect_uri` mismatch** — the callback URL doesn't exactly match `ISSUER` (`https`, no trailing slash, including any suffix Render added)
- **Deploy failed / health check** — `DATABASE_URL` unreachable; with Neon, append `?sslmode=require`. See the **Logs** tab on Render
- **Tokens invalid after a redeploy** — `RENKEI_JWKS` is empty. Check **Environment** — it's easy to skip when applying the Blueprint
